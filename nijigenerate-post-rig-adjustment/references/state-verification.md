# 状態・バインディング・保存の検証

## 変更前

njcで次を保存する。

- 対象パラメータUUID、軸、現在値、キーポイント。
- 対象Grid／Path／PartのUUID、型、親子関係、メッシュ頂点数。
- 対象キーの既存バインディング値と配列長。
- DepthRigRoot、DepthBone、BoneSourceの識別情報。
- GridDeformer深度、node Z、zSortなど変更禁止状態の監査値。
- 中立、問題キー、反対側、隣接キー、対角キーの画像。
- 非対象ノードと非対象パラメータのhashまたは同等の比較値。

`FileCommand_OpenFile`で状態を読み直さない。現在のnjcセッションからresourceを再読取する。

## 変更中

- `ParameditCommand_SetParameterKeypoint`など、現在schemaで確認した正確な操作でキーを設定する。
- 既存バインディングを読んでから差分を加える。
- ノードUUID、パラメータ値、配列長、頂点順の不一致で停止する。
- 一回の操作で一つの責任範囲だけを変更する。
- コマンド出力が曖昧でも再実行せず、resourceを読み戻して成功・失敗を判定する。

## 変更後

次を数値と画像の両方で確認する。

1. 対象キーで問題が解消した。
2. 中立キーの値と表示が一致する。
3. 隣接キーと対角キーで折れ、反転、過剰移動がない。
4. 変更したGrid／Path／Partと頂点数が予定どおりである。
5. 深度配列、node Z、zSort、DepthBone、BoneSourceが変わっていない。
6. 非対象パラメータと非対象ノードが変わっていない。
7. 標準Depthパラメータが再生成されていない。

## 保存

- ユーザーが明示的に上書きを求めない限り、新しい明示パスへ保存する。
- `FileCommand_SaveFile`だけで保存する。
- 保存後に対象バインディング、禁止状態、非対象hashを再読取する。
- 変更対象、キー、頂点、補正量、保存先を監査記録に残す。

読み戻しが一致しない場合は完了としない。

## 反転判定を誤った形状の固定に使わない

- 頂点対応・UV・実メッシュ被覆を確認し、中立の正常な面と現在の親寄与を基準に符号付き面積、潰れ、テクスチャの折れを調べる。変更前の角キーが既に反転している可能性を検査する。
- 変更前と符号が変わったという理由だけで候補を棄却しない。既存反転の解消と、新しい反転を分ける。遠側の投影・遮蔽による見かけの符号変化も、手前の可視面の折れと混同しない。
- 一つの三角形に引っ掛かったため補正全体を縮小すると、目標輪郭から外れた旧形状が残る。該当頂点と支持頂点、補正の連続性、既存残差を修正し、目標輪郭を保った状態で再検証する。数値ガードの通過は参照への一致の証明ではない。
- 編集したbinding内でも、非対象セル、保護された中立／Pitch=0、奥側などの頂点集合を個別に比較する。binding単位で監査対象から丸ごと除外しない。
