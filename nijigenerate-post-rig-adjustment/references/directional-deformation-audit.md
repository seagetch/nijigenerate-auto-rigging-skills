# 2軸パラメータの方向別変形監査

Face／BodyのYaw-Pitchなど、2軸パラメータで「各方向に何を変形したか」を説明・検証するときに使う。単なる姿勢画像一覧では変形の責任範囲を確認できないため、実メッシュとバインディング数値を同じ方向単位で対応させる。

## 必須の9状態

軸値は名前や配列位置で推測せず、対象Parameter resourceの`axisValues`から解決する。

| 表示 | 軸1 | 軸2 |
|---|---:|---:|
| 左上 | -1 | +1 |
| 上 | 0 | +1 |
| 右上 | +1 | +1 |
| 左 | -1 | 0 |
| 正面・中立 | 0 | 0 |
| 右 | +1 | 0 |
| 左下 | -1 | -1 |
| 下 | 0 | -1 |
| 右下 | +1 | -1 |

モデル固有の軸範囲が`-1／0／+1`でなければ、最小値・中立値・最大値へ読み替え、表示値を明記する。四隅だけ、または上下左右だけで完了しない。

## njcで取得する情報

`nijigenerate-shared-rigging-rules`に従ってnjc実行ファイルを解決する。環境固有の`out/njc`や絶対パスをスキルへ固定しない。

1. 対象Parameter、対象Grid／Path／Part、対象BindingのUUIDと現在値をresourceから読む。
2. `resource://nijigenerate/bindings/get?parameter=<PARAMETER>&target=<TARGET>&name=<BINDING>`を読み、`axisValues`、`isSet`、`values`、頂点数を保存する。
3. 対象Drawable resourceから中立頂点、インデックス、頂点順を読む。
4. `ParameditCommand_SetParameterKeypoint`を使い、上表の9状態を一つずつ正確に設定する。
5. 各状態で`ViewCommand_CaptureLiveScreenshot`を実行する。`overlayObjects`へ対象UUIDと`overlay: "mesh"`を指定し、画像と`overlayMappings`を同時に保存する。
6. `finally`相当の処理で必ず中立値へ戻す。

これは表示状態の一時変更であり、モデルBindingを変更しない。`FileCommand_OpenFile`、Computer Use、レビュアーSPA、`.inx`直接編集で代用しない。

## 変形の分離

方向画像を並べるだけでは、頭全体の移動と輪郭変形を区別できない。次の2種類を分けて示す。

### 実効メッシュ変形

中立の`overlayMappings.points[].image`を対象方向の同じ頂点へ2D similarity fitする。平行移動、回転、等倍拡縮を差し引き、方向画像上へ「位置合わせ済み中立メッシュ」を破線で重ねる。

- 現在メッシュ: njcが画像へ描いた実メッシュ。
- 位置合わせ済み中立メッシュ: 剛体的な姿勢差を除いた比較基準。
- 両者の差: 親Grid／Path、DepthRig、Partを含む最終的な非剛体変形。

raw画面座標をそのまま差し引かない。raw差分は顔や体全体の移動・回転を「輪郭変形」と誤認させる。

### 直接Binding変形

対象PartなどのBinding `values`を読み、どの頂点へ直接差分が入ったかを別に示す。

1. 中立頂点座標で画面左／画面右を分ける。キャラクター左右と混同しない。
2. 上部、上頬、中頬、下頬、顎など、画像で意味のある連続領域へ分ける。Bodyでは肩、胸、脇、腰などへ読み替える。
3. 各領域の移動頂点だけを集計し、平均`dx`、平均`dy`、対象頂点数を出す。
4. 方向画像へ番号付き矢印を重ね、同じ番号の表へ領域名と数値を置く。
5. 矢印を拡大表示する場合は、`4倍表示`など倍率を画像内へ明記する。数値自体は実値を表示する。

領域境界は固定のマジック座標にしない。対象メッシュの中立形状、輪郭、目・頬・顎などの位置を画像で確認して決め、監査記録へ境界または頂点集合を残す。微小値を表示から除く場合は閾値も記録する。

## 表示要件

各方向について、最低限次を一画面で対応付ける。

- 日本語の方向名と実際の軸値。
- 現在の実メッシュ。
- 位置合わせ済み中立メッシュ。
- 直接Bindingの領域別矢印。
- 領域別の平均`dx／dy`と頂点数。
- 符号規約: `dx-`は画面左、`dx+`は画面右、`dy-`は画面上、`dy+`は画面下。

静止画なら9状態を3×3に並べる。詳細数値が読めなくなる場合は、8方向を選択できる表示にして一方向ずつ画像と表を更新する。どちらの場合も、上下左右と四隅の全状態へ即座に到達できるようにする。

## 解釈

矢印の大小だけで良否を決めない。画像上で次を説明する。

- Yaw: 手前側の頬をどちらへ引き、奥側輪郭をどれだけ圧縮したか。
- Pitch: 顎だけを突出させず、上頬・下頬・顎をどう連続移動させたか。
- 四隅: YawとPitchの補正が同時に働いたとき、頬・顎・髪際の連続性が破綻していないか。
- 四辺・四隅: Face、Front Hair、Headwear、首、衣装など隣接部品とのocclusionが改善したか。

「平らにした」「凹凸を付けた」だけで説明しない。どの領域を、どちらへ、なぜ移動したかを、画像・メッシュ・Binding数値の三つで一致させる。

## 失敗として扱う表示

- 四隅だけを示し、上・下・左・右を省く。
- 方向名を付けた姿勢画像だけで、変形メッシュやBinding差分を示さない。
- パネル配置の「左上」と実際の顔向き「左上」を混同する。
- raw画面座標差を使い、全体移動を局所輪郭変形として説明する。
- 矢印倍率、符号規約、画面左右を示さない。
- Part Bindingを削除したように見えるUI画像だけで「効果がない」と判断し、resource読戻しをしない。
- 画像の見た目と数値の説明が逆方向になっている。

## 完了条件

- 9状態の画像寸法、対象UUID、頂点数、頂点順が一致する。
- 中立Bindingと中立表示が変更前と一致する。
- 8方向すべてに方向名、軸値、メッシュ比較、直接変形表がある。
- 表の`dx／dy`と画像上の矢印方向が一致する。
- 最後にパラメータが中立へ戻っている。
- この監査だけを行った場合、モデルファイルは保存・変更されていない。
